# Proposal: 階段詳情的使用者可讀輸出保留換行並在畫面寬度內折行

## Intent

**規範目的**：讓使用者在網頁控制台「階段詳情」裡讀到的每一段文字，都照原文的換行分段呈現，而且不會因為一長串沒有空白的字串（檔案路徑、網址、指令）撐出畫面、需要左右捲動。範圍涵蓋階段詳情顯示的所有使用者可讀輸出：分析摘要、執行計畫、確認結果、修改意見、執行摘要、審查等級、審查報告、執行日誌，以及待回覆提問的提示文字與選項按鈕文字。Markdown 原文照字面顯示（`#`、`-`、`|` 都看得到），不轉譯。

**規範背景**：分析摘要、執行摘要、審查報告、修改意見、執行日誌已經保留換行，但仍有兩個問題讓內容很難讀：

1. **待回覆提問的提示文字會把換行壓掉**。grilling 提問的提示是整段 `QUESTION: …` 加上 `1. …（建議）`、`2. …` 好幾行選項；人工確認的提示則是「## 執行計畫（共 N 個 TASK）」加上每個 TASK 一行，最後是「繼續執行？」。這些多行內容目前全部擠成一段，問題和選項黏在一起分不出來。
2. **過長、沒有空白的字串不會折行**。目前只在空白處換行，所以像 `tests/unit/user/views/userManagement/userListContainer/UsersListContainer.spec.js` 這種路徑，或是日誌裡一長串指令，會超出區塊寬度。執行計畫的每個 TASK 和選項按鈕文字也有同樣的問題。

**輸出要求**（本次只改呈現方式，不改資料內容）：

- 文字內容與後端提供的原文逐字相同，不增減、不重排、不轉譯 Markdown。
- 原文中的每一個換行都顯示成新的一行，連續空行也保留（段落間距跟原文一樣）；每行開頭的空白縮排也保留。
- 一行超過區塊寬度時，優先在空白處折行；遇到中間沒有可折斷位置的長字串，就在字串中間強制折行。區塊不出現水平捲軸，內容也不會超出區塊邊界。
- 執行日誌區塊維持現有的最大高度與垂直捲動。

**範例及解釋**：

- 範例一（grilling 提問）：analyze_plan 送出待回覆提問，提示文字是 `QUESTION: 這次要做到哪個程度？\n1. 純文字排版（建議）\n2. 轉譯 Markdown`。使用者點開 analyze_plan 卡片後，提示區看到三行：第一行是問題，第二、三行各是一個選項，跟終端機看到的分行一樣。選項按鈕照舊顯示在提示下方。
- 範例二（人工確認）：human_confirm 的提示包含「## 執行計畫（共 3 個 TASK）」、空一行，再列出 `1. …`、`2. …`、`3. …`，然後空一行接「繼續執行？」。使用者在詳情裡看到的分行與空行完全照這個結構，`##` 照字面顯示。
- 範例三（長路徑）：審查報告其中一行是 `` - `tests/unit/user/views/userManagement/userListContainer/UsersListContainer.spec.js`：新增 describe ``。在窄視窗裡，這一行先在空白處折行；那段沒有空白的路徑如果還是比區塊寬，就在路徑中間折到下一行。整個區塊不需要左右捲動。

## Scope

In scope:

- 階段詳情內所有使用者可讀輸出：分析摘要、執行計畫各項、確認結果、修改意見、執行摘要、審查等級、審查報告、執行日誌，都保留原文換行並在區塊寬度內強制折行
- 待回覆提問的提示文字保留原文換行並強制折行；選項按鈕文字過長時在按鈕內折行，不超出提問區塊
- 前端元件測試：驗證上述文字以「使用者可讀輸出」的呈現方式顯示，且提示文字的換行原樣保留
- `ARCHITECTURE.md` 前端段落同步說明這個呈現規則

Out of scope:

- Markdown 轉譯（標題、清單、表格、程式碼區塊的格式化顯示），也不新增 Markdown 套件
- 後端 API、`state.json` 欄位內容、`_log_event()` 印出的日誌格式
- 階段詳情以外的頁面（已封存任務、既有 Spec、規格搜尋、設定）
- 終端機（CLI）的顯示方式

## Approach

在 `web/frontend/src/style.css` 新增一個共用的 Tailwind `@utility`（`output-text`），內容是保留換行與空白、允許在任意位置強制折行。`StageDetail.vue` 和 `QuestionForm.vue` 裡所有顯示使用者可讀輸出的元素都改用這個 utility，取代各處零散的 `whitespace-pre-wrap`，讓規則只寫一次。細節見 `design.md`。
